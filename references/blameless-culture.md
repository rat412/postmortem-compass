# Blameless Culture — 不追责复盘的写作规则

复盘的目标是修复系统，不是审判个人。语言决定氛围：同一件事，换一种主语，团队下一次就还愿意上报故障。

## 改写规则 / Rewrite rules

| 追责式写法（禁止） | 系统性写法（采用） |
|---|---|
| 张三误删了生产数据库 | 删除命令未要求二次确认，且生产库缺少删除保护 |
| 李四没检查就上线了 | 发布流水线允许跳过预发验证步骤 |
| 值班的人没发现告警 | 该告警阈值高于实际故障表现，未触发通知 |
| 测试不充分 | 回归用例未覆盖该配置组合 |
| 他自己都承认是他搞砸的 | 变更操作缺少同行评审环节 |

## 三条硬规则

1. **人名只能出现在"参与者/贡献者"语境**（谁在救火、谁提供了关键信息），
   永远不能出现在"原因"语境。
2. **"人为失误"不是结论而是起点**。人为什么会犯错？是不是界面诱导、文档错误、
   告警疲劳、流程缺失？继续往下问。
3. **假设每个人都基于当时掌握的信息做了合理决策**。复盘要问的是：
   为什么那个决策在当时看起来是对的？系统如何让它变成了错的？

## 主持人的语气检查

写完通读一遍，对每个句子问：
- 这句话会不会让当事人下次选择隐瞒？会 → 重写。
- 这句话的主语是"人"还是"系统/流程/工具"？是人 → 尝试改写成系统。
- 这句话是描述事实还是评价动机？评价动机 → 删除。
